> 适用版本：v0.8.1

## 一、光鸭认证：两套体系不能混用

这是最容易踩的坑，配置前务必分清。

| | 网页端账号服务（普通用户用这个） | 官方 OpenAPI（高级用户） |
| --- | --- | --- |
| 域名 | `account.guangyapan.com` / `api.guangyapan.com` | `openapi.guangyapan.com` |
| 登录方式 | 手机号 + 短信验证码 | Device Code / Web PKCE |
| 凭证 | `access_token` + `refresh_token` + `did` | 开放平台应用凭证 |
| 业务接口认证头 | `Authorization: Bearer {token}` + `did` + `dt:4` | `x-client-id`（应用 ID）+ Bearer |
| 是否要去开放平台申请应用 | **不需要** | 需要，含 `project_id` / `sign_secret` |
| 本项目用途 | 文件列表、建/改/删分享、复制与建目录、任务状态 | 仅特定高级功能 |

- 普通用户只需在管理页「光鸭授权」输入手机号收验证码，凭证自动加密保存并到期刷新。
- 网页公开页面里的 `client_id`（形如 `aMe-8VSlkrbQXpUR`）**不是**开放平台应用 ID，不能拿去调官方 OpenAPI 业务接口，会报 `code=120`（应用 ID 错误）；反过来用短信凭证调官方 OpenAPI 也一样报错。
- `GuangYaOpenAPI._call` 有前置 guard：网页端凭证且没有 `client_id` 时直接报中文提示，防止错配漏出。
- 授权状态里的手机号 / 账号已脱敏（`utils.mask_account()`），`client_id` 属于应用 ID 不属于个人隐私，保留明文。

### 本项目实际调用的光鸭网页端接口

```http
POST /userres/v1/file/get_file_list   {"page":1,"pageSize":100,"parentId":"*","needSubFolderStat":true}
POST /userres/v1/share_file           # 创建分享
POST /userres/v1/update_share         # 修改分享
POST /userres/v1/delete_share         # 删除分享链接（不是删文件）
```

镜像复制（需求文档第八章确认）：

```http
POST /userres/v1/file/copy_file  {"fileIds":["..."],"parentId":"..."} → data.taskId
POST /userres/v1/get_task_status {"taskId":"..."}                     → data.status
```

v0.8.1 抓包 HAR 确认并落地的写接口：

```http
POST /userres/v1/file/create_dir   {"parentId":"...","dirName":"..."} → data.fileId
POST /userres/v1/file/rename       {"fileId":"...","newName":"..."}
POST /userres/v1/file/delete_file  {"fileIds":["...","..."]}          → data.taskId
```

- `create_dir` 用于 **A→B 目录自动镜像**；`rename` / `delete_file` 接口能力已具备，但主链路不调用（目录直接按目标名创建，且需求禁止「先删旧再复制」）。
- `status=2` 表示任务完成；**其它取值只原样记录 `raw_status` 并标 `unknown`，不猜成功或失败**，可在「镜像同步 → 继续轮询」里继续查。
- 没有 `taskId` / `fileId` 返回时直接报错，不标记完成，避免假成功。

### 仍未验证、因此未实现的接口

**只剩「投稿分享转存」**（TgtoDrive 侧 / 光鸭转存链路，本次 HAR 没有相关请求）。因此投稿只登记审核，不自动转存入库、不写 B 库、不触发推送。

前端 JS bundle 里还出现 `move_file` / `recycle_file` / `clear_recycle_bin` 等路径，但**只有字符串、没有请求体，本项目不实现、不猜参数**。详见 [光鸭接口取证](光鸭接口取证.md) 第四节。

## 二、A/B 目录 ID 怎么填

管理页「镜像同步 → A / B 库设置」需要两个 ID：

- **A 源头库目录 ID**：只读遍历的起点，存放原始资源。
- **B 镜像库目录 ID**：复制目标，也是扫描、资源库、分享、TG 分发的唯一来源。

获取方式：在光鸭网页端进入对应目录，从地址栏 `parentId` / 目录 `fileId` 或浏览器开发者工具网络面板里 `get_file_list` 请求的 `parentId` 字段读取。留空或填 `*` 代表根目录，**生产环境建议填具体目录 ID**，避免把整个网盘当成 A 库遍历。

> **v0.8.1 起扫描根目录不用再填一遍**：`_effective_scan_root()` 直接引用这里填的 B 库目录 ID（`ScanTask.root_id` / `.env SCAN_ROOT_ID` 只作兜底）。`GET /api/scan-task` 返回 `effective_root_id` 与 `root_source`，管理页「资源库 → 扫描计划」里只读展示。

> 待核实项：不同版本网页端地址栏参数名可能不同，以你实际看到的网络请求为准；本项目不提供目录 ID 自动枚举。

### 分类目录 1:1 镜像（v0.8.1）

A 库存在分类目录时，B 库按同样层级自动创建，**名字一个字都不改**：

```
A：动画电影 / 侠客行 (2001) {tmdb-135646} / Season 1 / E01.mkv
B：动画电影 / 侠*客*行 (2001) {tmdb-135646} / Season 1 / E01.mkv
     ↑ 分类原名        ↑ 只有影视主目录加 *        ↑ 子目录原名
```

| 目录类型 | B 库命名 | `MirrorDir.kind` |
| --- | --- | --- |
| 分类目录（动画电影 / 国产电影 / 欧美电影 / 日韩电影…） | **原名，不加 `*`** | `category` |
| 影视主目录 | 按下方 `*` 规则 | `work` |
| 季目录 / 子目录（Season 1…） | 原名 | `season` |

- `MirrorDir` 表记录每个目录的 A→B 映射（`status=mapped/created/missing`），`GET /api/mirror/status` 返回 `dirs` 与 `missing_dirs` 清单。
- 默认开启「B 库缺目录自动创建」；关闭时只登记待创建目录、相关作品标 `blocked`（不是 `failed`），不会把整批作品打成失败。
- 识别分类目录靠「目录名线索 + 子树是否直接含视频 + 是否像作品名」，不再把 A 根目录的直接子目录一律当影视主目录。

### B 库影视主目录命名规则

按需求文档，只有 **B 库影视主目录的主标题段**插入 `*`：

```
A：大醉侠 (2002) {tmdb-135646}
B：大*醉*侠 (2002) {tmdb-135646}
```

- **括号里的年份、TMDB 标记保持原样，前面只用空格分隔，不加 `*`**（v0.8.1 按用户反馈纠正）。
- 中文按字符插 `*`；纯英文按**单词**插 `*`（避免 `S*p*i*d*e*r` 式乱码目录名）。
- 展示、资源库、分享标题、TG 推送全部用标准影视名（`standard_media_name()`），不会把带 `*` 的名字推给用户。
- 归一化时 `normalize_work_name()` 会同时剥掉 `*` 和 `{tmdb-}` / 裸 `tmdb-` / `imdb-` 标记，保证 A/B 同剧落到同一个作品键，不裂成两张卡。

### 镜像配置参数

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| A / B 目录 ID | 镜像同步 → 设置 | 必填，缺失时「立即同步」直接报 400；B 库 ID 同时是扫描根目录 |
| 同步间隔 | 镜像同步 → 设置 | 按钮预设：10/15/30 分钟、1/2/6/12 小时、每天 |
| 启用 | 镜像同步 → 设置 | 关闭后定时任务注销，不自动同步 |
| `star_naming` | 镜像同步 → 设置 | B 库 `*` 命名模式开关 |
| `auto_create_dirs` | 镜像同步 → 设置 | **v0.8.1**：B 库缺目录时自动创建（默认开） |
| `file_idle_seconds` | 镜像同步 → 设置 | **v0.8.1**：每个文件操作后的空闲秒数，默认 1.0，范围 `[0.5, 60]` |
| `min_idle_seconds` | 只读展示 | **硬下限 0.5 秒**，来自官方写接口 2 次/秒限频，人为不可调低 |
| `auto_identify` | 镜像同步 → 设置 | 同步后是否做 B 库扫描 + 识别；即使开启也强制不推 TG |

`file_idle_seconds` 对**每次复制、建目录、变化更新**都生效；低于 0.5 秒后端直接返回 400。`get_task_status` 另有 0.2 秒轮询保护。

`GET /api/mirror/status` 可看到影视/文件映射数、目录映射数、自动创建目录数、待创建目录数、未知任务数、批次与变化事件数，以及已确认 / 待验证接口清单。

## 三、TgtoDrive OpenAPI 配置

TgtoDrive 是**独立外部系统**：Ya-TG 不集成它的源码、不部署它的容器、不读写它的数据库，只通过 OpenAPI 读写关键词规则。

管理页「互动中心 → TgtoDrive」填写：

| 配置键 | 说明 |
| --- | --- |
| `tgto_base_url` | TgtoDrive 服务根地址，例如 `http://<NAS内网IP>:<端口>`，末尾不要带 `/` |
| `tgto_api_key` | OpenAPI Token，鉴权头 `Authorization: Bearer <token>` |
| `tgto_scene` | 场景名，默认 `ENV_FILTER_GUANGYA` |
| `contribution_enabled` / `contribution_bot_token` | 投稿 Bot 开关与 Token |
| `donation_enabled` / `donation_image_url` / `donation_text` / `donation_button_text` | 打赏展示配置 |

所有配置走运行时加密落库，已登记进 `runtime_config.DEFAULTS`，不会出现「保存了但被静默忽略」。

### 接口与合并策略

```http
GET  {base}/api/visual-filter/config?scene=ENV_FILTER_GUANGYA
POST {base}/api/visual-filter/config
```

接口结构来自仓库同级 `tgto-openapi.json` 与 `guangya_visual_filter.json` 的实证。因为该接口**没有单条增删**，只能全量覆盖，Ya-TG 采取严格保守策略：

1. **GET 全量** → 2. 内存里只合并目标规则 → 3. **POST 回写** → 4. **回读校验**
5. 规则 id 用幂等格式 `kw_<tmdb_id>_<season>`（无 TMDB ID 时用 `kw_ya-tg_<标题slug>`）
6. 只新增或更新 `source=ya-tg` 的同 id 规则；**同 id 已存在且属于其它来源，直接返回 `conflict`，一次都不写回**，原有关键词、管理员手动规则、其它项目规则全部保留

「互动中心 → 测试连接」走 `POST /api/tgto/test`，只做只读探测，不会改动对方配置。

## 四、互动 Bot 配置

投稿 Bot 用 Telegram 官方 `getUpdates` / `sendMessage`，**不依赖光鸭抓包**。

1. 找 @BotFather 创建独立 Bot，拿 Token（建议与分发用的 Bot 分开）。
2. 「互动中心」填 `contribution_bot_token`，开启 `contribution_enabled`。
3. 「立即轮询」触发一次 `POST /api/bot/poll`；系统按 `contribution_update_offset` 增量拉取，不重复处理。

支持指令：

```
/want 剧名 [TMDB ID] [季]   提交想看的影视，自动合并关键词监控规则
/contribute 标题 [分享链接] 投稿资源，登记为 pending，由管理员审核
/donate                     查看打赏信息
/help                       查看说明
```

普通文本里带链接也会登记为投稿。投稿**只写 `user_contributions`，状态 `pending`**，不自动转存、不写 B 库、不触发任何推送；审核入口在「互动中心 → 投稿列表」。

## 五、.env 配置项

`.env.example` 保持极简，普通用户只需两项：

| 项 | 说明 |
| --- | --- |
| `ADMIN_PASSWORD` | 管理后台登录密码 |
| `APP_SECRET` | Fernet 加密主密钥，`openssl rand -hex 32` 生成 |
| `IMAGE_TAG` | 留空 = latest；锁版本填 `v0.8.1` |
| `WEB_PORT` / `WEB_BIND` | 网页端口与绑定地址 |
| `AUTO_CREATE_SHARE` / `SHARE_DURATION` | 分享策略 |
| `SCAN_CRON` / `SCAN_ROOT_ID` | 扫描计划（管理页改间隔按钮会覆盖 Cron；根目录以 B 库 ID 为准） |
| `TMDB_*` / `AI_*` | 可选，推荐在管理页填 |
| `TELEGRAM_API_BASE` | 可选，国内网络可填反代地址 |

`.env.example` 文末以注释形式保留 `GUANGYA_*` 高级凭证，普通用户不要填写。`tgto_*` / `contribution_*` / `donation_*` / v0.8.1 的 `file_idle_seconds` / `auto_create_dirs` **一律在管理页配置，`.env` 里没有也不需要这些项**。

数据库卷固定 `./db:/app/db`，`DATABASE_URL=sqlite:////app/db/ya-tg.db`；升级时**不要删 `db/` 目录**。v0.8.1 首次启动会自动补 `mirror_rules.file_idle_seconds` / `auto_create_dirs`、`mirror_media.category_path` 三列并新建 `mirror_dirs` 表。

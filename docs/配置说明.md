# 配置说明（光鸭 API / TgtoDrive OpenAPI / 互动 Bot / .env）

> 适用版本：v0.8.0
> 原则：**凭证与业务配置一律在管理页填写**，加密落库，改完立即生效、不用改 `.env`、不用重启容器。`.env` 只保留部署级参数。

---

## 一、光鸭认证：两套体系不能混用

这是最容易踩的坑，配置前务必分清。

| | 网页端账号服务（普通用户用这个） | 官方 OpenAPI（高级用户） |
| --- | --- | --- |
| 域名 | `account.guangyapan.com` / `api.guangyapan.com` | `openapi.guangyapan.com` |
| 登录方式 | 手机号 + 短信验证码 | Device Code / Web PKCE |
| 凭证 | `access_token` + `refresh_token` + `did` | 开放平台应用凭证 |
| 业务接口认证头 | `Authorization: Bearer {token}` + `did` + `dt:4` | `x-client-id`（应用 ID）+ Bearer |
| 是否要去开放平台申请应用 | **不需要** | 需要，含 `project_id` / `sign_secret` |
| 本项目用途 | 文件列表、建分享、复制文件、任务状态 | 仅特定高级功能 |

- 普通用户只需在管理页「光鸭授权」输入手机号收验证码，凭证自动加密保存并到期刷新。
- 网页公开页面里的 `client_id`（形如 `aMe-8VSlkrbQXpUR`）**不是**开放平台应用 ID，不能拿去调官方 OpenAPI 业务接口，会报 `code=120`（应用 ID 错误）；反过来用短信凭证调官方 OpenAPI 也一样报错。
- `GuangYaOpenAPI._call` 有前置 guard：网页端凭证且没有 `client_id` 时直接报中文提示，防止错配漏出。
- 授权状态里的手机号 / 账号已脱敏（`utils.mask_account()`），`client_id` 属于应用 ID 不属于个人隐私，保留明文。

### 本项目实际调用的光鸭网页端接口

已在代码里实现并有契约测试：

```http
POST https://api.guangyapan.com/userres/v1/file/get_file_list
     {"page":1,"pageSize":100,"parentId":"*","needSubFolderStat":true}

POST https://api.guangyapan.com/userres/v1/share_file        # 创建分享
POST https://api.guangyapan.com/userres/v1/update_share      # 修改分享
POST https://api.guangyapan.com/userres/v1/delete_share      # 删除分享链接（不是删文件）
```

需求文档第八章确认、v0.8.0 新增的镜像复制接口：

```http
POST https://api.guangyapan.com/userres/v1/file/copy_file
     {"fileIds":["1941911362609643616"],"parentId":"1969396537043607645"}
  →  {"msg":"success","data":{"taskId":"1970014019458977802"}}

POST https://api.guangyapan.com/userres/v1/get_task_status
     {"taskId":"1970014019458977802"}
  →  {"msg":"success","data":{"status":2}}
```

- `status=2` 表示复制完成；**其它取值只原样记录 `raw_status` 并标 `unknown`，不猜成功或失败**，可在「镜像同步 → 继续轮询」里继续查。
- 没有 `taskId` 返回时直接报错，不标记完成，避免假成功。

### 仍未验证、因此未实现的接口（需求文档 8.6）

创建文件夹、重命名文件夹（B 库自动加 `*`）、删除 B 库文件、删除目录 / 批量删除、投稿分享转存。

**影响**：B 库影视主目录需要你先在光鸭网页端手工建好；内容变化时旧文件不会自动删除（标为 `superseded` 保留）；投稿只登记审核，不自动转存。拿到这些接口的抓包 HAR 后才能补齐，本项目不会猜测参数去试。

## 二、A/B 目录 ID 怎么填

管理页「镜像同步」需要两个 ID：

- **A 源头库目录 ID**：只读遍历的起点，存放原始资源。
- **B 镜像库目录 ID**：复制目标，也是扫描、资源库、分享、TG 分发的唯一来源。

获取方式：在光鸭网页端进入对应目录，从地址栏 `parentId` / 目录 `fileId` 或浏览器开发者工具网络面板里 `get_file_list` 请求的 `parentId` 字段读取。留空或填 `*` 代表根目录，**生产环境建议填具体目录 ID**，避免把整个网盘当成 A 库遍历。

> 待核实项：不同版本网页端地址栏参数名可能不同，以你实际看到的网络请求为准；本项目不提供目录 ID 自动枚举，也不从 A 库推断 B 库结构。

### B 库目录命名规则

按需求文档，只有 **B 库影视主目录名**插入 `*`，年份、TMDB ID、季目录、单集文件名、A 库内容都不改。

```
A：大醉侠 (2002) {tmdb-135646}
B：大*醉*侠 *(2002) {tmdb-135646}
```

- 展示、资源库、分享标题、TG 推送全部用标准影视名（`standard_media_name()`），不会把带 `*` 的名字推给用户。
- 归一化时 `normalize_work_name()` 会同时剥掉 `*` 和 `{tmdb-}` / 裸 `tmdb-` / `imdb-` 标记，保证 A/B 同剧落到同一个作品键，不裂成两张卡。
- **重命名接口未验证**：v0.8.0 不会自动给 B 库改名，带 `*` 的目录需你手工建好。若 A 库作品在 B 库找不到对应目录，同步会跳过并记录原因（`test_mirror_missing_target_dir_is_skipped_not_created`），不会自动创建、更不会把文件复制到错误目录。

### 镜像配置参数

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| A / B 目录 ID | 镜像同步 → 设置 | 必填，缺失时「立即同步」直接报 400 |
| 同步间隔 | 镜像同步 → 设置 | 按钮预设：10/15/30 分钟、1/2/6/12 小时、每天 |
| 启用 | 镜像同步 → 设置 | 关闭后定时任务注销，不自动同步 |
| `star_naming` | 镜像同步 → 设置 | B 库 `*` 命名模式开关 |
| `auto_identify` | 镜像同步 → 设置 | 同步后是否做 B 库扫描 + 识别；即使开启也强制不推 TG |

`GET /api/mirror/status` 可看到影视映射数、已同步 / `superseded` 文件数、未知任务数、批次与变化事件数，以及这份「未验证接口清单」。

## 三、TgtoDrive OpenAPI 配置

TgtoDrive 是**独立外部系统**：Ya-TG 不集成它的源码、不部署它的容器、不读写它的数据库，只通过 OpenAPI 读写关键词规则。

管理页「互动中心 → TgtoDrive」填写：

| 配置键 | 说明 |
| --- | --- |
| `tgto_base_url` | TgtoDrive 服务根地址，例如 `http://<NAS内网IP>:<端口>`，末尾不要带 `/` |
| `tgto_api_key` | OpenAPI Token，鉴权头 `Authorization: Bearer <token>` |
| `tgto_scene` | 场景名，默认 `ENV_FILTER_GUANGYA` |
| `contribution_enabled` / `contribution_bot_token` | 投稿 Bot 开关与 Token |
| `donation_enabled` / `donation_image_url` / `donation_text` / `donation_button_text` | 打赏展示配置 |

所有配置走运行时加密落库，已登记进 `runtime_config.DEFAULTS`，不会出现「保存了但被静默忽略」。

### 接口与合并策略

```http
GET  {base}/api/visual-filter/config?scene=ENV_FILTER_GUANGYA
POST {base}/api/visual-filter/config
```

接口结构来自仓库同级 `tgto-openapi.json` 与 `guangya_visual_filter.json` 的实证。因为该接口**没有单条增删**，只能全量覆盖，Ya-TG 采取严格保守策略：

1. **GET 全量** → 2. 内存里只合并目标规则 → 3. **POST 回写** → 4. **回读校验**
5. 规则 id 用幂等格式 `kw_<tmdb_id>_<season>`（无 TMDB ID 时用 `kw_ya-tg_<标题slug>`）
6. 只新增或更新 `source=ya-tg` 的同 id 规则；**同 id 已存在且属于其它来源，直接返回 `conflict`，一次都不写回**，原有关键词、管理员手动规则、其它项目规则全部保留

「互动中心 → 测试连接」走 `POST /api/tgto/test`，只做只读探测，不会改动对方配置。

## 四、互动 Bot 配置

投稿 Bot 用 Telegram 官方 `getUpdates` / `sendMessage`，**不依赖光鸭抓包**。

1. 找 @BotFather 创建独立 Bot，拿 Token（建议与分发用的 Bot 分开）。
2. 「互动中心」填 `contribution_bot_token`，开启 `contribution_enabled`。
3. 「立即轮询」触发一次 `POST /api/bot/poll`；系统按 `contribution_update_offset` 增量拉取，不重复处理。

支持指令：

```
/want 剧名 [TMDB ID] [季]   提交想看的影视，自动合并关键词监控规则
/contribute 标题 [分享链接] 投稿资源，登记为 pending，由管理员审核
/donate                     查看打赏信息
/help                       查看说明
```

普通文本里带链接也会登记为投稿。投稿**只写 `user_contributions`，状态 `pending`**，不自动转存、不写 B 库、不触发任何推送；审核入口在「互动中心 → 投稿列表」。

## 五、.env 配置项

`.env.example` 保持极简，普通用户只需两项：

| 项 | 说明 |
| --- | --- |
| `ADMIN_PASSWORD` | 管理后台登录密码 |
| `APP_SECRET` | Fernet 加密主密钥，`openssl rand -hex 32` 生成 |
| `IMAGE_TAG` | 留空 = latest；锁版本填 `v0.8.0` |
| `WEB_PORT` / `WEB_BIND` | 网页端口与绑定地址 |
| `AUTO_CREATE_SHARE` / `SHARE_DURATION` | 分享策略 |
| `SCAN_CRON` / `SCAN_ROOT_ID` | 扫描计划（管理页改间隔按钮会覆盖 Cron） |
| `TMDB_*` / `AI_*` | 可选，推荐在管理页填 |
| `TELEGRAM_API_BASE` | 可选，国内网络可填反代地址 |

`.env.example` 文末以注释形式保留 `GUANGYA_*` 高级凭证，普通用户不要填写。`tgto_*` / `contribution_*` / `donation_*` **一律在管理页配置，`.env` 里没有也不需要这些项**。

数据库卷固定 `./db:/app/db`，`DATABASE_URL=sqlite:////app/db/ya-tg.db`；升级时**不要删 `db/` 目录**。

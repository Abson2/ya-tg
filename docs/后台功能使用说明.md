# 后台功能使用说明（v0.8.9）

> 侧栏导航：**概览 / 光鸭授权 / 镜像同步 / 资源库 / 分发规则 / 审核中心 / 推送队列 / TMDB 设置 / 消息模板 / 互动中心 / 操作审计**。
> **v0.8.1 起没有独立的「扫描设置」页**：扫描计划、断点与批次保护已折叠进「资源库」。
> **v0.8.3 起定时配置里不再有任何目录 ID 输入框**：扫描根目录自动引用镜像同步里填的 B 库 ID，后端也不再保存第二份 ID，改 B 库 ID 后下一次扫描立即生效。
> **v0.8.6 起 B 库单集 / 单电影文件名按英文剧名改名**：只换中文片名段，A 库与 B 库目录名不动，A→B 映射保持；存量文件到「镜像同步」点一次「按英文规范改名」，详见第一节。
> **v0.8.7 起三个刷新入口统一按 B 库最新内容重建资源库**：顶部「刷新」、资源库「立即扫描」、「重新扫描库」都会全量重扫 B 库，把 B 库已无的影视清出面板并取消分享；同时每轮镜像同步会核对 B 库实际文件，DB 标记已同步但 B 库确实缺失的自动补复制。详见第二节与第一节。
> **v0.8.8 起文件改名以 B 库实际文件名为准**：补复制回来的中文原名不会被「DB 记着已改名」跳过；同步结果提示带出「已达标跳过 / 无中文跳过 / 首个改名错误」，详见第一节。
> 基础操作见 `README.md` 第四节「首次使用向导」。

## 一、镜像同步

### 前置条件

1. 管理页「光鸭授权」已完成短信登录且凭证有效。
2. 在「镜像同步 → A / B 库设置」填好 A 源头库目录 ID 与 B 镜像库目录 ID。

**不再需要手工预建 B 库目录**：v0.8.1 已按抓包 HAR 落地 `create_dir` 接口，默认开启「B 库缺目录自动创建」，分类目录、影视主目录、季目录都会自动建好。接口取证见 `docs/光鸭接口取证.md`。

A 库全程只读；B 库才是扫描、资源库、分享和 Telegram 分发的唯一来源。

### 操作流程

1. 填 A/B 目录 ID，选同步间隔（10/15/30 分钟、1/2/6/12 小时、每天），按需设置文件空闲时间，打开「启用」，并按需开关「同步后自动入库识别并推送」（**v0.8.5 默认开启**）与「B 库单集/电影文件英文改名」（**v0.8.6 默认开启**）。保存后定时任务立即热更新，不用重启。
2. 点「立即同步」= `POST /api/mirror/run`（不传 `post_identify`，遵循开关）。流程：只读遍历 A → **识别分类目录链，找到真正的作品主目录** → 在 B 库 1:1 自动建目录（多层分类链逐层原名镜像）→ **只读核对 B 库实际文件，缺失的自动补复制** → `size:utime` 指纹比对 → 只复制新增/变化文件 → 调 `copy_file` 拿 `taskId` → 批量轮询 `get_task_status` → 单部影视完成即提交入库 → **按英文剧名改 B 库单集/单电影文件名** → **自动刷新 B 库入库 → 识别 → 只推本轮识别成功且有海报的影视**。
3. 三个按钮的区别：「立即同步」按开关；「强制入库识别」不管开关都执行完整链路；「仅同步」不管开关都只复制文件。停用时用「仅同步」随时止血。
4. 任务 `status=2` 且无错误码才算完成；`status=3` 或 `status=2` 且 `detail.code≠0` 判明确失败，下一轮同步自动重试；其它取值仍只记录原始值标 `unknown`。也可点「继续轮询任务」= `POST /api/mirror/tasks/poll` 继续查，任务确认完成后也会顺带改名。
5. 「同步状态」区可看影视/文件映射数、**目录已映射 / 自动创建目录 / 待创建目录**、复制失败/待重试文件、**已改英文名 / 改名失败 / 待翻译作品**、文件操作下限、已确认 / 待验证接口清单，以及生效配置里的「同步后自动入库识别并推送」「B 库单集/电影文件英文改名」实际值。

### 同步完没有自动入库 / 识别 / 推送（v0.8.5）

升级到 v0.8.5 前，`auto_identify` 只是存了、界面也显示，但手动与定时两条路径都没读它；「立即同步」按钮还硬编码跳过识别。本版已接通，排查顺序：

1. **看开关**：镜像设置「同步后自动入库识别并推送」是否为开；同步状态「生效配置」一栏回显的是**数据库里的真实值**，改完必须点「保存设置」。
2. **看返回**：点一次「立即同步」，结果提示末尾会带「自动入库 N 文件 · 识别成功 N · 入队 N · 内容变化待处理 N」。若显示「本次仅同步，未刷新入库」，说明开关关着或按了「仅同步」。
3. **看识别**：识别成功 + 拿到 TMDB 海报才会入队。未识别、无海报、作品在该频道已有队列项（含已发送）都不会再推。到资源库看识别状态与海报，或到「分发规则 → 链路自检」看卡在哪一步。
4. **看历史积压**：`内容变化待处理 N` 是**只读计数**，本版故意不处理这些历史事件，避免升级瞬间批量群推。用户主动点资源库「立即扫描 / 重新扫描库」时，才会按既有机制处理成一次作品级更新推送。

> 「镜像完成不是群推送」：自动链路只推**本轮识别成功**的影视，不会对全库补发，也不会回推历史已识别资源。不想让定时同步触发推送，直接关掉开关即可。

### 目录 1:1 镜像规则

```
A：动画电影 / 侠客行 (2001) {tmdb-135646} / Season 1 / E01.mkv
B：动画电影 / 侠·客·行 (2001) {tmdb-135646} / Season 1 / E01.mkv
     ↑ 分类原名        ↑ 只有主目录加 ·        ↑ 子目录原名
```

| 目录类型 | B 库命名 |
| --- | --- |
| 分类目录（动画电影 / 国产电影 / 欧美电影 / 日韩电影…） | **原名，不加标记、不改名**（原名里的中点也保留） |
| 影视主目录 | v0.8.3 起主标题按 `·` 规则（网盘拒绝 `*`）；**括号里的年份与 TMDB 标记保持原样** |
| 季目录 / 子目录 | 原名 |

- 「目录映射清单」列出每个目录的类别、所属分类、状态（`mapped` / `created` / `missing`）与 B 库目录 ID。
- 「待创建目录」只在关闭自动创建（或建目录失败）时出现，给出父目录 ID 与处理建议。相关作品标为 **`blocked`，不是 `failed`**，建好目录后重新同步即可继续。
- 旧版本把「动画电影」误当成作品而留下的空 `failed` 记录会被自动清理，不再显示为「47 部全部失败」。

### 文件操作风控间隔

- 「每个文件操作后的空闲时间（秒）」默认 1.0 秒，可调高到 60 秒；**每次复制、建目录、变化更新前都会等待**。
- **硬下限 0.5 秒来自官方写接口 2 次/秒限频，人为不可调低**：输入框有 `min` 约束，后端低于 0.5 秒直接返回 400。调大更安全，代价是同步变慢。
- 任务轮询另有 0.2 秒保护；批量任务先一起提交再统一等待，避免逐条阻塞放大耗时。

### 同步后自动入库识别并推送（v0.8.5）

`POST /api/mirror/run` 不传参数时按 `auto_identify` 开关决定是否接完整链路：B 库全量扫描刷新入库 → TMDB 识别 → **只把本轮识别成功且有海报的影视按分发规则入队推送**。显式 `post_identify=true` 强制执行、`false` 只复制文件。

v0.8.4 及更早版本这里写死 `publish_after_identify=False`，识别结果不会入队；该红线已按用户明确要求反转。但「**镜像完成不是群推送**」仍然成立：不补发全库、不回溯历史已识别资源、不批量补推历史内容变化事件。

### 同步没成功时怎么排查（v0.8.2 起，v0.8.3 补充）

看到「待创建目录」一堆 `missing`、作品全是 `blocked`、文件数 0 时，按这个顺序看：

1. **同步状态 → 生效配置**：先确认「B 库缺目录自动创建」是「开启」。若显示红色「关闭（会全部 blocked）」，打开开关、保存设置再同步。
2. **待创建目录 → 失败原因**：这里显示 `create_dir` 接口的真实报错，不再是通用文案。
   - `B 镜像库根目录不可访问…` → 核对 B 库目录 ID、目录是否存在、光鸭登录态是否有效。
   - `文件夹名包含非法字符: *`（code=141）→ **v0.8.3 起不会再出现**：主目录标记已改为 `·`，旧带 `*` 名称就地转换；v0.8.2 已降级创建的无标记目录直接复用，不会重复建目录。只有连 `·` 也被拒绝时才会降级为无标记标准名（`created_fallback`）。
   - `无权限 / 会员 / 限频` 等其它报错 → 按错误本身处理，必要时导出容器日志。
3. **容器日志**：`docker compose logs --no-color --since 1h ya-tg > ya-tg.log 2>&1`，日志里有 `[mirror]` 前缀的建目录失败与同步异常记录。
4. 修正后点「立即同步」，已有的 `blocked` 记录会被复用并恢复为 `synced`，不需要清库。

### 目录建好了、命名也对，但里面没有文件（v0.8.4）

这是与上面完全不同的另一段链路。按顺序看：

1. **同步状态**：看「复制失败」「待重试文件」「失败任务」三个计数，以及 `last_message` 里的「复制失败 N · 首个文件错误：…」。v0.8.4 之前文件级错误只存在于点完同步的那一次弹窗里，刷新就没了。
2. **文件复制失败 / 待重试**清单：显示作品名、文件名、任务 ID 和 `copy_file` / `get_task_status` 的真实报错。常见两类：
   - `复制请求失败 code=… msg=…` → `copy_file` 本身被网盘拒绝（权限、空间、参数、登录态）；
   - `复制任务 … 失败（云盘空间不足 / status=3）` → 任务被网盘判失败，v0.8.3 会把它误显示成「待确认」。
3. **直接再点一次「立即同步」**：v0.8.4 起 `copying` / `failed` / `unknown` 的文件会**自动重试**，不再像旧版那样被当成「已存在」永久跳过。重试前会先只读列 B 库，任务其实已成功但轮询超时的文件会直接回填成 `synced`，不会重复复制。
4. 若是历史遗留的「待确认」任务，也可以点「轮询任务」继续查询；明确失败的任务会把文件标 `failed`，下一轮同步自动重试。
5. **清单里全部指向 `copy_file` 时**：该接口目前只有前端 JS 契约、没有真实抓包证据。请在网页端手动执行一次「复制到」并抓 HAR（步骤见 `docs/光鸭接口取证.md` 第十节），脱敏后提供，用于核对请求体与错误码。

> 不需要清库、不需要删 B 库空目录：修复后复用现有目录映射与文件记录即可，已复制成功的文件不会被重复推送或重复复制。

### B 库影视文件夹下是空目录（v0.8.7 补齐根因）

v0.8.4 只修了 `copying` / `failed` / `unknown` 被当成 unchanged 永久跳过；**DB 标记 `synced` 同样不等于 B 库真的有文件**——文件在 B 库被删、换了 B 库目录、复制任务报成功却没落地时，记录会永远停在 `synced`，再点几次「立即同步」都是「未变」，作品目录一直是空的。

v0.8.7 起每轮同步对每部作品只读递归列一次 B 库目录树：

| 情况 | 行为 |
| --- | --- |
| 列目录完整可信 + 确实找不到 | 复用同一 `MirrorFile` 行重置为 `pending` 自动补复制，`file_name` 仍是 A 原名，A→B 映射不丢 |
| 列目录失败 / 分页不完整 / 层级超 60 | 一律不动 `synced`，防接口抖动重复复制 |
| B 库文件数不少于已同步记录数 | 绝不重置，只记 `name_mismatch`（多半是改名 / 重名加后缀） |
| 文件在 `作品/Season 1/1080p/` 更深层 | 递归遍历找到，不误判为空 |

同步结果提示与「同步状态」会带「B库缺失补复制 N · 名称不符 N」，文件级原因进 `file_errors[]`。**升级到 v0.8.7 后点一次「立即同步」即可自愈历史空目录**，不需要清库、不需要删空目录。

### B 库单集/电影文件英文改名（v0.8.6）

**背景**：v0.8.5 的自动链路已能推送，但影视文件审核不通过——B 库里的单集 / 单电影文件名仍带中文剧名。本版只改这些**文件名**，不动 A 源头库，也不动 B 库的分类目录、影视主目录（`·` 命名）和季目录。

1. 镜像设置打开「B 库单集/电影文件英文改名」（默认开）并保存。之后每次「立即同步」/ 定时同步 / 任务轮询确认完成后，会在扫描入库**之前**自动改名。
2. **存量文件**：升级后已经同步过的文件不会自动改名，点一次「按英文规范改名」= `POST /api/mirror/rename` 即可，不重新复制、不改变任何目录。
3. 英文名解析：优先 TMDB `en-US` 官方片名，日韩作品或 TMDB 不可用时走 AI 翻译中文剧名；每部作品只解析一次并缓存。想重解析就点「重新解析英文名并改名」（`force=true`）。
4. 命名效果：`大醉侠 第04集 2160p.WEB-DL.H.265.mkv` → `The Drunk Hero 第04集 2160p.WEB-DL.H.265.mkv`。只换中文片名段，季集号、年份、画质、编码、压制组、扩展名（含其中文）原样保留。
5. **绝不瞎猜**：文件名本来就是 ASCII、英文名解析不到或含中文、目标名不合法，一律跳过并计入「无中文跳过」。解析不到英文剧名的作品进「英文名待处理」清单——先检查 TMDB 密钥是否有效，或到「TMDB 设置 / AI 辅助识别」补齐配置，再点「重新解析英文名并改名」。
6. 改名失败看「改名失败」清单：失败原因落库、刷新页面仍在，单个文件失败不影响其他文件；修好原因后再点一次按钮即可（已成功的不会重复改）。
7. 同步结果提示会带「改名 N · 待翻译作品 N · 改名失败 N」；状态卡另有「已改英文名 / 改名失败 / 待翻译作品」三个计数。

> **映射不丢**：改名结果单独存 `MirrorFile.target_name`，`file_name` 永远是 A 库原名；A→B 映射与变量更新比对用的是 `source_file_id + size:utime` 指纹，与文件名无关。列 B 库核对时会优先按新名字反查，所以改名后下一轮不会误判「文件不存在」而重复复制。

### 补复制后汉字名称没翻译（v0.8.8）

现象：同步结果「重试 N · 完成 N · **改名 0 · 待翻译作品 0 · 改名失败 0**」，文件确实补回来了，但单集 / 电影文件名仍是中文。

原因：v0.8.7 的空目录补复制把文件从 A 库重新复制成**中文原名**，但复用同一条映射记录时只重置了 `target_file_id`，`rename_status=done` / `target_name=英文名` 残留，改名环节按 DB 幂等整批跳过。纯命名规则没问题，问题在状态机。

v0.8.8 两条修复：① 补复制时同步清空 `target_name` / `rename_status` / `rename_error`；② 改名改为**以 B 库实际文件名为准**——列目录后按 `fileId` 反查当前文件名，只有 B 库当前名确实是目标英文名才跳过（并纠正 DB 状态），否则一律重新改名。列目录失败时仍退回 DB 幂等判断，防接口抖动误改。

**升级后点一次「立即同步」即可自愈**，不需要清库、重新复制或重建数据库；也可直接点「按英文规范改名」/「重新解析英文名并改名」。同步结果提示现在会带「改名 N · 已达标跳过 N · 无中文跳过 N · 待翻译作品 N · 改名失败 N」以及「无待改名文件 N 部」「首个改名错误：…」；整体异常还会写进「同步状态」的 `last_message`，刷新页面仍在。

### 边界提醒（重要）

- 内容变化不会「先删旧再复制」：旧 B 文件保留并标 `superseded`，只新增复制记录。`delete_file` 接口虽已取证实现，但按需求约束**主链路不调用**，旧文件需要你在网盘端人工清理。
- 身份用 `TMDB ID + 类型 + 季 + 集`。身份不明确时只允许新增，**禁止自动替换**。
- 镜像模块本身不写 `push_queue`。但镜像后 B 库扫描产生的「内容变化事件」会留在库里，后续任一次常规扫描 / 重新扫描库会按分发规则处理成**一次作品级更新推送**。这是「内容变化 → 一次更新推送」的设计，不是逐集轰炸；若你要求镜像带来的变化绝对不推，见 `docs/需求追踪矩阵.md` 未完成项 ③。

## 二、扫描计划（在「资源库」里）

原「扫描设置」页已合并。v0.8.7 起三个刷新入口统一按 B 库最新内容重建（详见第二节）：

| 按钮 | 作用 |
| --- | --- |
| 顶部「刷新」 | `POST /api/library/refresh`，全量重扫 B 库并按实际内容重建面板 |
| 立即扫描 | `POST /api/scan-now`，与顶部「刷新」同一管线，统一全量扫描并自动识别新资源 |
| 重新扫描库 | `POST /api/library/rescan`，同一管线，结果额外带识别 / 完结回填统计 |
| 扫描计划 | 展开/收起扫描计划、断点状态、批次保护三块内容 |

### 扫描根目录：只读引用，不用再填

「扫描根目录」输入框已改为只读展示：

- 默认显示 `effective_root_id`，即**「镜像同步 → B 镜像库目录 ID」**，来源标为「镜像同步 · B 库目录 ID（自动引用）」。
- 想换扫描范围，去「镜像同步」改 B 库 ID 即可，这里会自动跟着变。
- 只有未配置镜像时，才会回退到扫描计划旧值或 `.env SCAN_ROOT_ID`。
- `scan_now` / `rescan_library` / 定时扫描三条路径统一走同一个有效根目录，不会出现「镜像写 B、扫描却扫了 A」的错配。

### 时间间隔按钮

默认每 30 分钟。直接点预设按钮即可，不用手写 Cron；高级用户可展开「自定义 Cron」（五段表达式，Asia/Shanghai）。保存会热更新调度任务，免重启。

### 扫描批次列表

每轮扫描都会留一条 `resource_scan_batches` 记录，列表展示状态、文件数、`seen` 数、`complete`、是否允许对账。

**常规批次只有同时满足「全量、全部分页读取成功、`seen` 非空、`reconcile_allowed=true`」时才允许对账删除资源。** v0.8.7 起用户主动刷新额外允许「**可信空批次**」清库：批次 `success` + `complete` + 非断点 + `directories>0` + `seen_count=0`（B 库确实一个视频都没有）。其余情况一律跳过，不删资源、不取消分享：

- 任一 API 请求失败
- 分页不完整（含接口提前返回空页的隐藏短页）
- 扫描中断 / 任务被取消
- 断点续扫（`resumed=true`）
- B 库无法访问、扫描结果异常

批次表是唯一权威信号，不靠调用方口头声明「我扫完了」。

### 三个刷新入口统一重建（v0.8.7）

用户口径：「资源库里面刷新定义为读取最新的 B 库内容，B 库文件夹已无该影视则清理出面板」。**顶部「刷新」、资源库「立即扫描」、「重新扫描库」三个入口从 v0.8.7 起完全一致**，都走 `main._refresh_library_from_b()`：`run_scan(B 库, resume=False)` → 对账移除 → 自动识别 → 内容变化处理。

| 入口 | API | 行为 |
| --- | --- | --- |
| 顶部「刷新」 | `POST /api/library/refresh` | 全量重建，B 库已无的影视清出面板并取消分享 |
| 资源库「立即扫描」 | `POST /api/scan-now` | 同上；`resume` 参数仅为兼容旧调用保留，统一全量 |
| 资源库「重新扫描库」 | `POST /api/library/rescan` | 同上，结果提示额外带「识别 N 项、完结回填 N 项」 |

| | 三个刷新入口（用户主动） | 定时扫描 / 镜像后自动管线 |
| --- | --- | --- |
| 断点 | 强制全量 | 定时扫描按配置；镜像后管线强制全量 |
| 自动识别 | 是 | 是 |
| 对账删除 | **是**，受批次授权约束 | **否**（保持不自动删数据） |
| 完结回填 | 是 | 是 |
| 空批次清库 | 仅「可信空批次」允许 | 不允许 |

**可信空批次**门槛：批次 `status=success` + `complete` + 非断点续扫 + **确实扫到目录**（`directories>0`）+ `seen_count=0`。B 库根目录都读不到、批次失败 / 不完整 / 断点续扫时一律跳过，返回 `empty_scan_untrusted` / `batch_not_allowed`，接口抖动不会误清整个资源库。前端提示会带「B 库为空，面板已按实际内容清空」。

全量重扫耗时较长，前端三个入口统一放宽到 180 秒超时。

## 三、资源库

### 作品墙

按整部作品聚合成作品卡（不再逐集罗列），展示海报、完结/追更角标、分享效期角标。可勾选多张卡做批量操作：修改分享效期、取消分享、重新分享、重新识别。

### 电影也按作品目录分享（v0.8.1 修复）

旧逻辑只有剧集会计算目录分享，电影一律分享**单文件**，导致用户拿到的是一集/一个文件而不是整部作品目录。

- 现在电影与剧集统一走作品目录分享：电影的**作品目录 = 直接父目录**。
- 例外：电影文件直接散放在「国产电影」这类分类目录下（父目录名像分类、又没有年份 / TMDB 标记）时，退化为按文件分享，**避免把整个分类目录当成一部电影分享出去**。
- 分享标题、TG 推送仍用标准影视名，不带 `*`。

### 完结状态手动修正

TMDB 判错完结状态时，在作品卡点「完结状态 ▾」：

| 选项 | 效果 |
| --- | --- |
| 标记完结（锁定） | 整部作品所有单集置 `ended`，`finish_locked=true` |
| 标记追更（锁定） | 整部作品置 `returning`，`finish_locked=true` |
| 清除状态（锁定） | 清空状态，仍锁定，防止自动回填再填错 |
| 恢复 TMDB 自动判断 | 清空并解锁，后续自动识别可重新回填 |

锁定后角标会显示「·手动」。**TMDB 自动回填、扫描后自动识别、手动重新识别都不会覆盖人工判断**。批量操作条也支持同样的 `set_finish`。

### 完结校验

点「完结校验」= `GET /api/library/finish-check`，用 TMDB 的季数 / 已播出集数与 B 库实际文件数做**只读**比对，给出「应有集 / 本地集 / 缺集 / 建议」。它不会自动改状态，确认识别有误后再用上面的下拉标记。

### 重新扫描库 / 清空

- 「顶部「刷新」/「立即扫描」/「重新扫描库」」（v0.8.7 三入口统一）：全量重扫 B 库 → 批次授权后按实际内容对账移除已删除的影视（删除前先取消分享、清队列；可信空批次可清空面板）→ 自动识别 → 完结回填 → 处理内容变化事件。
- 「清空当前扫描结果」：只清 `Resource` / `QueueItem` / `ScanCursor` 以及变化留痕，保留所有配置和已建分享，用来清掉错误残留。

升级老版本后目录链 / `path_hint` / `share_dir_id` 可能缺失，标准动作是：**先「重新扫描库」，再对需要的作品「重新识别」**。

## 四、内容变化更新的实际行为

扫描发现文件 `size/utime` 变化时：

1. 只写一条 `resource_versions` 版本留痕，**不重建分享、不取消再创建**，原分享链接继续用。
2. 同一批里同一部作品的多集变化按「作品 + 变化指纹」合并成**唯一一条** `distribution_events`。
3. 处理时复用原有队列项重置为待发送（或只入一条），因此是**一次作品级更新推送**，不逐集重复推。
4. 没有变化就不产生事件，不会空推。

## 六、排障入口

| 现象 | 先看哪里 |
| --- | --- |
| 推送没生效 | `GET /api/diagnostics`（管理页「链路自检」），指出卡在 Bot / 频道 / 规则 / 待审核 / 失败哪一步，带 `last_error` 与 retry 状态。**不要直接改入队逻辑** |
| 同步结果异常 | 「镜像同步 → 同步状态」的 `last_message`（v0.8.1 会保留异常类型，不再是笼统 502）；「待创建目录」「目录映射清单」两张表 |

| 单资源推送 | `POST /api/resources/{id}/publish` 返回 `detail[]`（队列项状态与错误）与 `skipped[]`（规则不符、频道/Bot 停用的原因） |

## 日志保留与清理（v0.8.3）

「操作审计」页顶部新增「日志保留与清理」卡片，解决所有日志/留痕只增不减、SQLite 无限膨胀的问题。

- **保留天数**（默认 30）、**每类日志上限**（默认 5000 条）、**自动清理**开关：保存后立即生效。自动清理在容器启动时与每天 03:30（北京时间）各执行一次。
- 「立即清理」按当前策略删；「清空全部日志」需二次确认，会把所有可清理的历史记录一次清掉（会保留一条 `logs_cleared` 审计）。
- 表格列出每类日志的总条数、可清理条数、最早/最新时间，以及「绝不删除」的保护规则。
- **保护红线**：running 扫描批次、pending/running 镜像任务、待处理分发事件、pending/retry/review 队列项、当前生效的文件映射一律保留；资源、目录映射、分享链接根本不在清理范围。
- 容器 stdout 日志由 compose 的 `json-file` 限额 `3 × 10MB` 控制，不需要手工删除 `./logs`。

> 资源库「扫描计划」里已没有「扫描根目录」输入框，也不必再填镜像库 ID；改「镜像同步 → B 镜像库目录 ID」即可。

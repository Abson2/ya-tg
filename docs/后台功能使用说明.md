# 后台功能使用说明（v0.8.0）

> 侧栏导航：**概览 / 资源库 / 授权 / 分发规则 / 消息模板 / 扫描设置 / 镜像同步 / 互动中心 / 审计**。
> 本文档只讲 v0.8.0 新增或改动的部分；基础操作见 `README.md` 第四节「首次使用向导」。

## 一、镜像同步

### 前置条件（不满足会直接跳过，不会乱复制）

1. 管理页「光鸭授权」已完成短信登录且凭证有效。
2. 在光鸭网页端**手工建好 B 库影视主目录**，并按 `*` 规则命名（见 `docs/配置说明.md` 第二节）。创建/重命名接口尚未验证，本项目不会自动建目录、不会自动改名。
3. 在「镜像同步 → 设置」填好 A 源头库目录 ID 与 B 镜像库目录 ID。

A 库全程只读；B 库才是扫描、资源库、分享和 Telegram 分发的唯一来源。

### 操作流程

1. 「设置」里填 A/B 目录 ID，选同步间隔（10/15/30 分钟、1/2/6/12 小时、每天），打开「启用」。保存后定时任务立即热更新，不用重启。
2. 点「立即同步」= `POST /api/mirror/run`。流程：只读遍历 A → 按作品主目录分组 → `size:utime` 指纹比对 → 只复制新增/变化文件 → 调 `copy_file` 拿 `taskId` → 轮询 `get_task_status` → **单部影视完成即提交入库**。
3. 若某任务返回的 `status` 不是 `2`，不会判定成功也不会判定失败，只记录原始值并标为 `unknown`。稍后点「继续轮询」= `POST /api/mirror/tasks/poll` 继续查。
4. 「状态」区可看影视映射清单、已同步 / `superseded` 文件数、未知任务数，以及尚未验证的接口清单。

### 勾选「同步后识别」时

`POST /api/mirror/run?post_identify=true` 会额外做一次 B 库全量扫描 + TMDB 识别，**但强制 `publish_after_identify=False`，不会把识别结果自动入队推 TG**。想推送时，走资源库正常的「立即推送」或分发规则链路。

### 边界提醒（重要）

- 内容变化不会「先删旧再复制」：旧 B 文件保留并标 `superseded`，只新增复制记录。删除接口未验证，旧文件需要你在网盘端人工清理。
- 身份用 `TMDB ID + 类型 + 季 + 集`。身份不明确时只允许新增，**禁止自动替换**，避免把不同作品/季集的文件覆盖掉。
- 镜像模块本身不写 `push_queue`。但镜像后 B 库扫描产生的「内容变化事件」会留在库里，后续任一次常规扫描 / 重新扫描库会按分发规则处理成**一次作品级更新推送**。这是「内容变化 → 一次更新推送」的设计，不是逐集轰炸；若你要求镜像带来的变化绝对不推，见 `docs/需求追踪矩阵.md` 未完成项 ③。

## 二、扫描设置

### 时间间隔按钮

默认每 30 分钟。直接点预设按钮即可，不用手写 Cron；高级用户可展开「自定义 Cron」（五段表达式，Asia/Shanghai）。设置保存会热更新调度任务，免重启。

### 扫描批次列表

每轮扫描都会留一条 `resource_scan_batches` 记录，列表展示状态、文件/目录数、`seen` 数、`complete`、`resumed`、是否允许对账。

**只有一条批次同时满足「全量、全部分页读取成功、`seen` 非空、`reconcile_allowed=true`」时，才允许对账删除资源。** 以下情况一律跳过，不删资源、不取消分享：

- 任一 API 请求失败
- 分页不完整（含接口提前返回空页的隐藏短页）
- 扫描中断 / 任务被取消
- 断点续扫（`resumed=true`）
- B 库无法访问、扫描结果异常

批次表是唯一权威信号，不靠调用方口头声明「我扫完了」。

### 定时扫描 vs 重新扫描库

| | 定时扫描 / 立即扫描 | 资源库「重新扫描库」 |
| --- | --- | --- |
| 入口 | 扫描设置 / `POST /api/scan-now` | 资源库按钮 / `POST /api/library/rescan` |
| 断点 | 默认续扫 | 强制全量 |
| 自动识别 | 是 | 是 |
| 对账删除 | **否**（防接口抖动误删） | 是，但受批次授权约束 |
| 完结回填 | 是 | 是 |

全量重扫耗时较长，前端单独放宽到 180 秒超时。

## 三、资源库

### 作品墙

按整部作品聚合成作品卡（不再逐集罗列），展示海报、完结/追更角标、分享效期角标。可勾选多张卡做批量操作：修改分享效期、取消分享、重新分享、重新识别。

### 完结状态手动修正

TMDB 判错完结状态时，在作品卡点「完结状态 ▾」：

| 选项 | 效果 |
| --- | --- |
| 标记完结（锁定） | 整部作品所有单集置 `ended`，`finish_locked=true` |
| 标记追更（锁定） | 整部作品置 `returning`，`finish_locked=true` |
| 清除状态（锁定） | 清空状态，仍锁定，防止自动回填再填错 |
| 恢复 TMDB 自动判断 | 清空并解锁，后续自动识别可重新回填 |

锁定后角标会显示「·手动」。**TMDB 自动回填、扫描后自动识别、手动重新识别都不会覆盖人工判断**。批量操作条也支持同样的 `set_finish`。

### 完结校验

点「完结校验」= `GET /api/library/finish-check`，用 TMDB 的季数 / 已播出集数与 B 库实际文件数做**只读**比对，给出「应有集 / 本地集 / 缺集 / 建议」。它不会自动改状态，确认识别有误后再用上面的下拉标记。

### 重新扫描库 / 清空

- 「重新扫描库」：全量重扫 → 批次授权后对账移除网盘里已删除的影视（删除前先取消分享、清队列）→ 自动识别 → 完结回填 → 处理内容变化事件。
- 「清空当前扫描结果」：只清 `Resource` / `QueueItem` / `ScanCursor` 以及变化留痕，保留所有配置和已建分享，用来清掉错误残留。

升级老版本后目录链 / `path_hint` / `share_dir_id` 可能缺失，标准动作是：**先「重新扫描库」，再对需要的作品「重新识别」**。

## 四、内容变化更新的实际行为

扫描发现文件 `size/utime` 变化时：

1. 只写一条 `resource_versions` 版本留痕，**不重建分享、不取消再创建**，原分享链接继续用。
2. 同一批里同一部作品的多集变化按「作品 + 变化指纹」合并成**唯一一条** `distribution_events`。
3. 处理时复用原有队列项重置为待发送（或只入一条），因此是**一次作品级更新推送**，不逐集重复推。
4. 没有变化就不产生事件，不会空推。

## 五、互动中心

| 区块 | 操作 |
| --- | --- |
| TgtoDrive | 填地址 / Token / 场景 → 「测试连接」只读探测 → 保存 |
| 投稿 Bot | 填独立 Bot Token → 开启 → 「立即轮询」拉 `getUpdates` |
| 投稿列表 | 查看 `pending` 投稿 → 手工标记处理；**不自动转存、不写 B 库、不触发推送** |
| 我想看 | 手工添加关键词，按 `kw_<tmdb>_<season>` 幂等合并到 TgtoDrive；同 id 属其它来源会报 `conflict` 且不写回 |
| 打赏 | 配置图片、文案、按钮文字 |

Bot 指令：`/want` `/contribute` `/donate` `/help`。详细配置见 `docs/配置说明.md` 第三、四节。

## 六、排障入口

推送没生效时**先看 `GET /api/diagnostics`**（管理页「链路自检」），它会指出卡在 Bot / 频道 / 规则 / 待审核 / 失败哪一步，并带 `last_error` 与 retry 状态。不要直接改入队逻辑。

其它常用：`POST /api/resources/{id}/publish` 返回 `detail[]`（队列项状态与错误）与 `skipped[]`（规则不符、频道/Bot 停用的原因）。

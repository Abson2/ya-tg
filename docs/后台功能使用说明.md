# 后台功能使用说明（v0.8.4）

> 侧栏导航：**概览 / 光鸭授权 / 镜像同步 / 资源库 / 分发规则 / 审核中心 / 推送队列 / TMDB 设置 / 消息模板 / 互动中心 / 操作审计**。
> **v0.8.1 起没有独立的「扫描设置」页**：扫描计划、断点与批次保护已折叠进「资源库」。
> **v0.8.3 起定时配置里不再有任何目录 ID 输入框**：扫描根目录自动引用镜像同步里填的 B 库 ID，后端也不再保存第二份 ID，改 B 库 ID 后下一次扫描立即生效。
> 基础操作见 `README.md` 第四节「首次使用向导」。

## 一、镜像同步

### 前置条件

1. 管理页「光鸭授权」已完成短信登录且凭证有效。
2. 在「镜像同步 → A / B 库设置」填好 A 源头库目录 ID 与 B 镜像库目录 ID。

**不再需要手工预建 B 库目录**：v0.8.1 已按抓包 HAR 落地 `create_dir` 接口，默认开启「B 库缺目录自动创建」，分类目录、影视主目录、季目录都会自动建好。接口取证见 `docs/光鸭接口取证.md`。

A 库全程只读；B 库才是扫描、资源库、分享和 Telegram 分发的唯一来源。

### 操作流程

1. 填 A/B 目录 ID，选同步间隔（10/15/30 分钟、1/2/6/12 小时、每天），按需设置文件空闲时间，打开「启用」。保存后定时任务立即热更新，不用重启。
2. 点「立即同步」= `POST /api/mirror/run`。流程：只读遍历 A → **识别分类目录链，找到真正的作品主目录** → 在 B 库 1:1 自动建目录 → `size:utime` 指纹比对 → 只复制新增/变化文件 → 调 `copy_file` 拿 `taskId` → 批量轮询 `get_task_status` → 单部影视完成即提交入库。
3. 若某任务返回的 `status` 不是 `2`，不会判定成功也不会判定失败，只记录原始值并标为 `unknown`。稍后点「继续轮询」= `POST /api/mirror/tasks/poll` 继续查。
4. 「同步状态」区可看影视/文件映射数、**目录已映射 / 自动创建目录 / 待创建目录**、未知任务数、文件操作下限，以及已确认 / 待验证接口清单。

### 目录 1:1 镜像规则

```
A：动画电影 / 侠客行 (2001) {tmdb-135646} / Season 1 / E01.mkv
B：动画电影 / 侠·客·行 (2001) {tmdb-135646} / Season 1 / E01.mkv
     ↑ 分类原名        ↑ 只有主目录加 ·        ↑ 子目录原名
```

| 目录类型 | B 库命名 |
| --- | --- |
| 分类目录（动画电影 / 国产电影 / 欧美电影 / 日韩电影…） | **原名，不加标记、不改名**（原名里的中点也保留） |
| 影视主目录 | v0.8.3 起主标题按 `·` 规则（网盘拒绝 `*`）；**括号里的年份与 TMDB 标记保持原样** |
| 季目录 / 子目录 | 原名 |

- 「目录映射清单」列出每个目录的类别、所属分类、状态（`mapped` / `created` / `missing`）与 B 库目录 ID。
- 「待创建目录」只在关闭自动创建（或建目录失败）时出现，给出父目录 ID 与处理建议。相关作品标为 **`blocked`，不是 `failed`**，建好目录后重新同步即可继续。
- 旧版本把「动画电影」误当成作品而留下的空 `failed` 记录会被自动清理，不再显示为「47 部全部失败」。

### 文件操作风控间隔

- 「每个文件操作后的空闲时间（秒）」默认 1.0 秒，可调高到 60 秒；**每次复制、建目录、变化更新前都会等待**。
- **硬下限 0.5 秒来自官方写接口 2 次/秒限频，人为不可调低**：输入框有 `min` 约束，后端低于 0.5 秒直接返回 400。调大更安全，代价是同步变慢。
- 任务轮询另有 0.2 秒保护；批量任务先一起提交再统一等待，避免逐条阻塞放大耗时。

### 勾选「同步后识别」时

`POST /api/mirror/run?post_identify=true` 会额外做一次 B 库全量扫描 + TMDB 识别，**但强制 `publish_after_identify=False`，不会把识别结果自动入队推 TG**。想推送时，走资源库正常的「立即推送」或分发规则链路。

### 同步没成功时怎么排查（v0.8.2 起，v0.8.3 补充）

看到「待创建目录」一堆 `missing`、作品全是 `blocked`、文件数 0 时，按这个顺序看：

1. **同步状态 → 生效配置**：先确认「B 库缺目录自动创建」是「开启」。若显示红色「关闭（会全部 blocked）」，打开开关、保存设置再同步。
2. **待创建目录 → 失败原因**：这里显示 `create_dir` 接口的真实报错，不再是通用文案。
   - `B 镜像库根目录不可访问…` → 核对 B 库目录 ID、目录是否存在、光鸭登录态是否有效。
   - `文件夹名包含非法字符: *`（code=141）→ **v0.8.3 起不会再出现**：主目录标记已改为 `·`，旧带 `*` 名称就地转换；v0.8.2 已降级创建的无标记目录直接复用，不会重复建目录。只有连 `·` 也被拒绝时才会降级为无标记标准名（`created_fallback`）。
   - `无权限 / 会员 / 限频` 等其它报错 → 按错误本身处理，必要时导出容器日志。
3. **容器日志**：`docker compose logs --no-color --since 1h ya-tg > ya-tg.log 2>&1`，日志里有 `[mirror]` 前缀的建目录失败与同步异常记录。
4. 修正后点「立即同步」，已有的 `blocked` 记录会被复用并恢复为 `synced`，不需要清库。

### 目录建好了、命名也对，但里面没有文件（v0.8.4）

这是与上面完全不同的另一段链路。按顺序看：

1. **同步状态**：看「复制失败」「待重试文件」「失败任务」三个计数，以及 `last_message` 里的「复制失败 N · 首个文件错误：…」。v0.8.4 之前文件级错误只存在于点完同步的那一次弹窗里，刷新就没了。
2. **文件复制失败 / 待重试**清单：显示作品名、文件名、任务 ID 和 `copy_file` / `get_task_status` 的真实报错。常见两类：
   - `复制请求失败 code=… msg=…` → `copy_file` 本身被网盘拒绝（权限、空间、参数、登录态）；
   - `复制任务 … 失败（云盘空间不足 / status=3）` → 任务被网盘判失败，v0.8.3 会把它误显示成「待确认」。
3. **直接再点一次「立即同步」**：v0.8.4 起 `copying` / `failed` / `unknown` 的文件会**自动重试**，不再像旧版那样被当成「已存在」永久跳过。重试前会先只读列 B 库，任务其实已成功但轮询超时的文件会直接回填成 `synced`，不会重复复制。
4. 若是历史遗留的「待确认」任务，也可以点「轮询任务」继续查询；明确失败的任务会把文件标 `failed`，下一轮同步自动重试。
5. **清单里全部指向 `copy_file` 时**：该接口目前只有前端 JS 契约、没有真实抓包证据。请在网页端手动执行一次「复制到」并抓 HAR（步骤见 `docs/光鸭接口取证.md` 第十节），脱敏后提供，用于核对请求体与错误码。

> 不需要清库、不需要删 B 库空目录：修复后复用现有目录映射与文件记录即可，已复制成功的文件不会被重复推送或重复复制。

### 边界提醒（重要）

- 内容变化不会「先删旧再复制」：旧 B 文件保留并标 `superseded`，只新增复制记录。`delete_file` 接口虽已取证实现，但按需求约束**主链路不调用**，旧文件需要你在网盘端人工清理。
- 身份用 `TMDB ID + 类型 + 季 + 集`。身份不明确时只允许新增，**禁止自动替换**。
- 镜像模块本身不写 `push_queue`。但镜像后 B 库扫描产生的「内容变化事件」会留在库里，后续任一次常规扫描 / 重新扫描库会按分发规则处理成**一次作品级更新推送**。这是「内容变化 → 一次更新推送」的设计，不是逐集轰炸；若你要求镜像带来的变化绝对不推，见 `docs/需求追踪矩阵.md` 未完成项 ③。

## 二、扫描计划（在「资源库」里）

原「扫描设置」页已合并。资源库页头新增两个按钮：

| 按钮 | 作用 |
| --- | --- |
| 立即扫描 | `POST /api/scan-now`，扫描 B 库并自动识别新资源 |
| 扫描计划 | 展开/收起扫描计划、断点状态、批次保护三块内容 |

### 扫描根目录：只读引用，不用再填

「扫描根目录」输入框已改为只读展示：

- 默认显示 `effective_root_id`，即**「镜像同步 → B 镜像库目录 ID」**，来源标为「镜像同步 · B 库目录 ID（自动引用）」。
- 想换扫描范围，去「镜像同步」改 B 库 ID 即可，这里会自动跟着变。
- 只有未配置镜像时，才会回退到扫描计划旧值或 `.env SCAN_ROOT_ID`。
- `scan_now` / `rescan_library` / 定时扫描三条路径统一走同一个有效根目录，不会出现「镜像写 B、扫描却扫了 A」的错配。

### 时间间隔按钮

默认每 30 分钟。直接点预设按钮即可，不用手写 Cron；高级用户可展开「自定义 Cron」（五段表达式，Asia/Shanghai）。保存会热更新调度任务，免重启。

### 扫描批次列表

每轮扫描都会留一条 `resource_scan_batches` 记录，列表展示状态、文件数、`seen` 数、`complete`、是否允许对账。

**只有一条批次同时满足「全量、全部分页读取成功、`seen` 非空、`reconcile_allowed=true`」时，才允许对账删除资源。** 以下情况一律跳过，不删资源、不取消分享：

- 任一 API 请求失败
- 分页不完整（含接口提前返回空页的隐藏短页）
- 扫描中断 / 任务被取消
- 断点续扫（`resumed=true`）
- B 库无法访问、扫描结果异常

批次表是唯一权威信号，不靠调用方口头声明「我扫完了」。

### 定时扫描 vs 重新扫描库

| | 定时扫描 / 立即扫描 | 资源库「重新扫描库」 |
| --- | --- | --- |
| 入口 | 资源库页头「立即扫描」 / `POST /api/scan-now` | 资源库按钮 / `POST /api/library/rescan` |
| 断点 | 默认续扫 | 强制全量 |
| 自动识别 | 是 | 是 |
| 对账删除 | **否**（防接口抖动误删） | 是，但受批次授权约束 |
| 完结回填 | 是 | 是 |

全量重扫耗时较长，前端单独放宽到 180 秒超时。

## 三、资源库

### 作品墙

按整部作品聚合成作品卡（不再逐集罗列），展示海报、完结/追更角标、分享效期角标。可勾选多张卡做批量操作：修改分享效期、取消分享、重新分享、重新识别。

### 电影也按作品目录分享（v0.8.1 修复）

旧逻辑只有剧集会计算目录分享，电影一律分享**单文件**，导致用户拿到的是一集/一个文件而不是整部作品目录。

- 现在电影与剧集统一走作品目录分享：电影的**作品目录 = 直接父目录**。
- 例外：电影文件直接散放在「国产电影」这类分类目录下（父目录名像分类、又没有年份 / TMDB 标记）时，退化为按文件分享，**避免把整个分类目录当成一部电影分享出去**。
- 分享标题、TG 推送仍用标准影视名，不带 `*`。

### 完结状态手动修正

TMDB 判错完结状态时，在作品卡点「完结状态 ▾」：

| 选项 | 效果 |
| --- | --- |
| 标记完结（锁定） | 整部作品所有单集置 `ended`，`finish_locked=true` |
| 标记追更（锁定） | 整部作品置 `returning`，`finish_locked=true` |
| 清除状态（锁定） | 清空状态，仍锁定，防止自动回填再填错 |
| 恢复 TMDB 自动判断 | 清空并解锁，后续自动识别可重新回填 |

锁定后角标会显示「·手动」。**TMDB 自动回填、扫描后自动识别、手动重新识别都不会覆盖人工判断**。批量操作条也支持同样的 `set_finish`。

### 完结校验

点「完结校验」= `GET /api/library/finish-check`，用 TMDB 的季数 / 已播出集数与 B 库实际文件数做**只读**比对，给出「应有集 / 本地集 / 缺集 / 建议」。它不会自动改状态，确认识别有误后再用上面的下拉标记。

### 重新扫描库 / 清空

- 「重新扫描库」：全量重扫 → 批次授权后对账移除网盘里已删除的影视（删除前先取消分享、清队列）→ 自动识别 → 完结回填 → 处理内容变化事件。
- 「清空当前扫描结果」：只清 `Resource` / `QueueItem` / `ScanCursor` 以及变化留痕，保留所有配置和已建分享，用来清掉错误残留。

升级老版本后目录链 / `path_hint` / `share_dir_id` 可能缺失，标准动作是：**先「重新扫描库」，再对需要的作品「重新识别」**。

## 四、内容变化更新的实际行为

扫描发现文件 `size/utime` 变化时：

1. 只写一条 `resource_versions` 版本留痕，**不重建分享、不取消再创建**，原分享链接继续用。
2. 同一批里同一部作品的多集变化按「作品 + 变化指纹」合并成**唯一一条** `distribution_events`。
3. 处理时复用原有队列项重置为待发送（或只入一条），因此是**一次作品级更新推送**，不逐集重复推。
4. 没有变化就不产生事件，不会空推。

## 六、排障入口

| 现象 | 先看哪里 |
| --- | --- |
| 推送没生效 | `GET /api/diagnostics`（管理页「链路自检」），指出卡在 Bot / 频道 / 规则 / 待审核 / 失败哪一步，带 `last_error` 与 retry 状态。**不要直接改入队逻辑** |
| 同步结果异常 | 「镜像同步 → 同步状态」的 `last_message`（v0.8.1 会保留异常类型，不再是笼统 502）；「待创建目录」「目录映射清单」两张表 |
| 作品被跳过 | 影视映射清单 `status=blocked` = 缺 B 库目录，开启自动建目录或按清单建好后重新同步；**不是失败** |
| 分享是单文件 | 确认资源已重新扫描 + 重识别，`share_scope` 应为 `series_dir`；若父目录是分类目录则按设计退化为文件分享 |
| 单资源推送 | `POST /api/resources/{id}/publish` 返回 `detail[]`（队列项状态与错误）与 `skipped[]`（规则不符、频道/Bot 停用的原因） |

## 日志保留与清理（v0.8.3）

「操作审计」页顶部新增「日志保留与清理」卡片，解决所有日志/留痕只增不减、SQLite 无限膨胀的问题。

- **保留天数**（默认 30）、**每类日志上限**（默认 5000 条）、**自动清理**开关：保存后立即生效。自动清理在容器启动时与每天 03:30（北京时间）各执行一次。
- 「立即清理」按当前策略删；「清空全部日志」需二次确认，会把所有可清理的历史记录一次清掉（会保留一条 `logs_cleared` 审计）。
- 表格列出每类日志的总条数、可清理条数、最早/最新时间，以及「绝不删除」的保护规则。
- **保护红线**：running 扫描批次、pending/running 镜像任务、待处理分发事件、pending/retry/review 队列项、当前生效的文件映射一律保留；资源、目录映射、分享链接根本不在清理范围。
- 容器 stdout 日志由 compose 的 `json-file` 限额 `3 × 10MB` 控制，不需要手工删除 `./logs`。

> 资源库「扫描计划」里已没有「扫描根目录」输入框，也不必再填镜像库 ID；改「镜像同步 → B 镜像库目录 ID」即可。

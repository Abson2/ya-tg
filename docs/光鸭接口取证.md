## 二、HAR 里直接抓到的写接口（请求体 + 响应体）

### 1. 创建目录

```http
POST https://api.guangyapan.com/userres/v1/file/create_dir
Content-Type: application/json
Authorization: Bearer <redacted>
did: <redacted>
dt: 4
```

```json
{"parentId": "1969396537043607645", "dirName": "新建文件夹-20261118144906745"}
```

```json
{
  "msg": "success",
  "data": {
    "fileId": "1970043394325770305",
    "fileName": "新建文件夹-20261118144906745",
    "parentId": "1969396537043607645",
    "depth": 2,
    "dirType": 1,
    "resType": 2,
    "fullParentIds": "1969396537043607645/",
    "ctime": 1794984546,
    "utime": 1794984546
  }
}
```

要点：`data.fileId` 是新建目录的 ID；`resType=2` 表示目录。**没拿到 `fileId` 时本项目直接报错，不标记完成、不假装成功。**

### 2. 重命名

```json
{"fileId": "1970043394325770305", "newName": "我"}
→ {"msg": "success"}
```

### 3. 删除（支持批量）

```json
{"fileIds": ["1970043394325770305"]}
→ {"msg": "success", "data": {"taskId": "1970043471073169483"}}
```

```json
{"fileIds": ["1970041880160612426", "1969937245395582978"]}
→ {"msg": "success", "data": {"taskId": "1970043548978171928"}}
```

要点：`fileIds` 是数组，支持一次删多个；返回 `taskId`，**必须再查任务状态才算完成**。

### 4. 任务状态

```json
{"taskId": "1970043471073169483"}
→ {"msg": "success", "data": {"status": 2}}
```

`status=2` 表示完成。其它取值本项目只原样记录 `raw_status` 并标 `unknown`，**不猜成功或失败**，可继续轮询。

### 5. 需求文档第八章已确认、本次 HAR 未重复抓到请求体的接口

```http
POST /userres/v1/file/copy_file  {"fileIds":["..."],"parentId":"..."} → data.taskId
```

`copy_file` 的 URL 与请求体来自《tg-gy 最终版项目开发需求文档》第八章，v0.8.0 已按原文实现并有契约测试锁死；本次 HAR 的 JS bundle 里也出现了该路径，可作为路径存在的旁证，但**没有请求体样本，不改动既有实现**。

## 三、代码落地位置

| 接口 | 客户端方法 | 主链路是否调用 |
| --- | --- | --- |
| `create_dir` | `GuangYaWebFiles.create_dir()` | **是**：`mirror.sync_rule()` → `_ensure_child()` 自动建 A→B 分类目录、影视主目录、季目录 |
| `rename` | `GuangYaWebFiles.rename_file()` | 否：B 库目录**直接按目标名创建**，不需要「先建后改名」 |
| `delete_file` | `GuangYaWebFiles.delete_files()` | 否：需求明确**禁止「先删旧再复制」**，旧文件保留并标 `superseded` |
| `get_task_status` | `GuangYaWebFiles.get_task_status()` | 是：复制任务批量轮询 |
| `copy_file` | `GuangYaWebFiles.copy_file()` | 是：增量复制 |

> 说明：`rename` / `delete_file` 的**接口能力已经具备并有契约测试**，但主链路按需求约束不调用。需要「改名已有目录」或「清理 `superseded` 旧文件」时，须显式新增上层动作，不能让镜像同步偷偷删东西。

契约测试：`tests/test_v081_mirror_dirs.py::test_web_write_endpoints_match_har_contract` 与 `::test_only_transfer_remains_unverified`。

## 五、限频与风控依据

- 官方 OpenAPI v1.3 §10：写接口 **2 次/秒**限频；文件列表接口 5 次/秒。
- 因此项目设 `MIN_FILE_IDLE_SECONDS = 0.5` 为**硬下限，人为不可调低**：`MirrorRule.file_idle_seconds` 只能调高（默认 1.0 秒，上限 60 秒），前端 `min` 与后端 400 校验双重约束。
- 每次 `copy_file` / `create_dir` / 变化更新前按 `max(配置值, 0.5)` 等待；`get_task_status` 另有 0.2 秒轮询保护；任务先批量提交再统一等待，避免逐条阻塞。

## 六、仍需真实环境验证的点

自动化测试只锁死「URL / 请求体 / 响应结构」，以下必须有真实账号才能确认：

1. `create_dir` 返回后 B 库目录是否**立即可见**（是否需要等待索引刷新）。
2. 目录名含 `*`、`(2002)`、`{tmdb-...}` 等字符时，网页端是否原样接受。
3. `copy_file` 复制到新建分类目录 / 作品目录 / 季目录的真实表现与 `status` 非 2 的取值语义。
4. A 库真实分类层级下 `_discover_works()` 的作品主目录判定是否与实际一致。
5. 文件空闲时间是否足以避开风控。

## 七、如何补抓「投稿分享转存」的 HAR

这是需求文档 8.6 唯一剩下的未验证项。Ya-TG 不会猜测参数，需要一次真实请求样本。

1. Chrome / Edge 打开光鸭网页端并登录，按 `F12` → **Network**，勾选 **Preserve log**（保留跨页请求）。
2. 在「清空」之后，**只做一次目标动作**：把一个分享链接转存 / 保存到自己的网盘（或触发投稿入库的动作）。动作前后不要混入无关操作，便于定位。
3. 右键请求列表 → **Save all as HAR with content**（必须带 content，否则没有请求体 / 响应体）。
4. 用随仓库交付的工具生成脱敏摘要，**不要直接把 HAR 发给任何人**：

```bash
python3 scripts/har_extract.py /路径/到/转存.har -o 转存接口摘要.md --host guangyapan.com
# 只看写接口：
python3 scripts/har_extract.py /路径/到/转存.har --only transfer,save,copy,share -o 转存接口摘要.md
```

5. 脚本会输出：命中的 URL、请求体、响应体（凭证已打码）、`base64` 解码结果，以及前端 JS 里的接口路径清单；末尾会做一次「JWT / 手机号 / Bearer 凭证残留」自检。
6. 打开摘要**人工确认一遍**，再放进对话或提交 issue。拿到带请求体的转存接口后，就能补上 H11，`UNVERIFIED_ENDPOINTS` 也随之清空。

> 注意：JS 字符串里出现的路径（如 `move_file`）**不算证据**，必须有当次操作的真实请求体与响应体。

## 八、`create_dir` 在真实环境的失败排查（v0.8.2）

HAR 里 `create_dir` 是在网页端手工新建文件夹时抓到的，返回 `200 / msg=success / data.fileId`。但镜像同步实际调用时，B 库目录 ID、写入权限、目录名字符都可能与抓包场景不同。v0.8.2 之前这些错误会被界面通用文案吞掉，导致「42 部作品全 missing、看不出为什么」。

现在的处理链路：

1. `sync_rule()` 先用 `get_file_list` 预检 B 库根目录；不可读直接抛 `WebFileError`，消息含 B 库目录 ID 与接口原始错误，**不会**逐部作品试建目录。
2. `_ensure_child()` 调 `create_dir`，失败原因写入 `MirrorDir.error`，并进 `stats["dir_errors"]` / `rule.last_message` / 容器日志 `[mirror]`。
3. `/api/mirror/status` 把 `error` 原样回显到「待创建目录 → 失败原因」，同时返回 `config` 回显开关与目录 ID。
4. 若报错与目录名有关（例如网盘拒绝 `*`），自动用不带 `*` 的标准影视名重试一次，成功后整轮沿用标准名，标记 `created_fallback`。

排障时请提供：`docker compose logs --no-color --since 1h ya-tg > ya-tg.log 2>&1` 生成的日志，或管理页「同步状态 → 生效配置」+「待创建目录 → 失败原因」两处截图。**不要把原始 HAR 或未脱敏日志直接发出去。**

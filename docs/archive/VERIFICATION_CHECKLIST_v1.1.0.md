## 1. P0 镜像写锁与顺序（本版核心修复）
- [ ] 1.1 **写锁根治（真机原报错点）**：跑英文名解析（原报 `database is locked` 的 `West Out of Yumen` 类作品），并发跑镜像/扫描，`UPDATE mirror_media SET english_title` 不再抛 `database is locked` / `SQLITE_BUSY_SNAPSHOT`
- [ ] 1.2 **先复制后批量改名**：观察一轮镜像，先把整部剧所有文件复制到 B 库完成，再进入统一的英文名解析/批量改名阶段；不再"边复制边改"
- [ ] 1.3 **英文名四层解析未退化**：中文片名（如新济公活佛）仍能解析出英文名（缓存→Resource→TMDB→AI→拼音，用户明确不动）
- [ ] 1.4 **按名+大小回填未退化**：轮询超时后按名+大小回填 fileId，映射正确（用户明确不动）
- [ ] 1.5 **strict 严格顺序**（可选开）：`strict=true` 跑一轮，按 S01E01→S01E02 自然序复制；暂停/恢复/跳过/取消四操作在任务表留终态
- [ ] 1.6 **镜像后不群推**：镜像动作本身不触发群推（publish=false 红线）

## 2. P0 四模块主链（默认接管，无需手动开）
> 本版 `share_center_enabled` 默认 `true`，发布走分享中心主链；`/api/share/center/status` 返回 `{enabled:true, counts, queues, share_records}`。
- [ ] 2.1 **首次分享（规则1）**：一部剧识别入库 → 分享中心出现 1 条 first 任务 → 按整剧目录建 1 个分享 → submitted→accepted→published，TG 收到 1 条
- [ ] 2.2 **追更新推送（规则1）**：给已分享剧集新增集数后重新扫描 → 出现 1 条 update 任务（parent_task_id 指向首次任务），**复用原分享链接**（URL 不变），但 TG **再次收到**推送
- [ ] 2.3 **交接确认（强制项4）**：跑一轮观察队列项 submitted→accepted→published，记录 accept_worker/accepted_at；两个 worker 并发时同一任务只被领取一次（不重复推送）
- [ ] 2.4 **B 库删除闭环（规则2）**：B 库删掉整部剧 → 重新扫描 → 资源库出库 + 分享任务 cancelled + 光鸭原分享取消；A 库仍有该文件 → 下一轮镜像补齐 B 库 → 重新入库 → 新 first 任务 → 重新分享推送
- [ ] 2.5 **三类队列与总览**：分享中心页显示 全新/存量/追更/有效分享 四个总数，三队列筛选能正确过滤任务
- [ ] 2.6 **手动强推**：点资源「立即推送」→ force 任务（priority 最高、不去重、绕过海报门禁），仍走 TG 发送
- [ ] 2.7 **分享失败降级**：模拟建分享失败（凭证失效）→ 消息仍送达但无链接，任务状态如实记录，推送不被阻断
- [ ] 2.8 **配额门禁**：设 `fresh_daily_quota=1`，当天第 2 部新剧不推送（任务停在门禁），配额可配
- [ ] 2.9 **立即推送自驱动**：无需等 5s job，点「立即推送」后很快送达（publisher 内自驱 run_cycle）

## 3. P0 安全
- [ ] 3.1 **路径穿越封死**：`curl --path-as-is 'http://<host>:8787/../db/ya-tg.db'`、`/%2e%2e/db/ya-tg.db` 返回非 200 或不含敏感内容
- [ ] 3.2 **会话过期**：设 `ADMIN_IDLE_MINUTES=1`，闲置 2 分钟后任意业务请求返回 401 并跳登录页
- [ ] 3.3 **浏览器不存明文**：登录后在 localStorage 查 `ya_tg_password` 不存在、只有会话 token
- [ ] 3.4 **弱口令拒绝**：`ADMIN_PASSWORD=CHANGE_ME` 或 `123456` 启动，登录被拒
- [ ] 3.5 审计脱敏：触发带 token 的操作后，审计日志 detail 里 token 被掩码

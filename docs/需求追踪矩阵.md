# 需求追踪矩阵（对照《tg-gy 最终版项目开发需求文档 V1.0》/《V2.0》）

> 版本基线：`v0.8.9`（2026-11-18）；v0.8.7 commit `aa1f32c`，v0.8.6 commit `ae62a3c`，v0.8.5 commit `414ac5d`，v0.8.4 commit `beed009`，v0.8.3 commit `0d7afff`，v0.8.1 commit `b99ec77`，v0.8.0 基线 commit `663d1fe`
> 状态口径：**只按代码与测试的实际状态填写**，不把「写了页面」「写了字段」算作完成。
> 条款编号以原始需求文档为准，本表按能力域归组，便于逐条打勾复核。

## 图例

| 标记 | 含义 | 判定标准 |
| --- | --- | --- |
| ✅ 已实现 | 主链路闭环 | 代码 + 单元测试/契约测试同时覆盖，且不依赖未验证的外部接口 |
| 🟡 部分实现 | 代码存在但闭环有缺口 | 有实现，但依赖人工步骤、外部真实环境，或隔离只靠约定没有数据层强制 |
| ⏳ 待验证 | 接口已按文档实现 | URL/请求体有契约测试，但没有真实账号/真实返回的联调记录 |
| ❌ 未实现 | 明确未做 | 缺少已验证接口，按需求文档 8.6 保留为待验证，**不猜测参数** |

结论先行：**主干能力已实现并有 215 项回归测试覆盖；v0.8.8 修掉「补复制回来的文件是中文原名却因 DB 残留改名状态被整批跳过」的问题，改名改为以 B 库实际文件名为准并补齐跳过原因诊断；v0.8.7 修掉「B 库影视文件夹下为空目录」的根因（DB 标记 `synced` 不等于 B 库真有文件，改为每轮只读核对并自动补复制），统一三个刷新入口按 B 库实际内容重建资源库，并补齐多层分类树 1:1 镜像；v0.8.6 按用户实测反馈把 B 库单集 / 单电影文件名改为英文剧名（只换中文片名段，A 库与 B 库目录名不动，A→B 映射靠文件 ID + 指纹保持）；v0.8.5 按用户明确口径接通「镜像完成 → 刷新入库 → 识别 → 只推本轮识别成功且有海报的影视」，反转了 v0.8.0~v0.8.4 写死的「镜像完成不自动推送 Telegram」红线，但保留了「不是群推送」的边界（不批量补推历史内容变化事件）**。v0.8.4 修掉「B 库目录建好、命名正常，但文件没镜像过去」，v0.8.3 修了 `*` → `·`、根目录重复配置与日志膨胀，v0.8.2 修了建目录失败诊断，v0.8.1 落地 HAR 取证的写接口，但仍不能声明「全面功能实现」。剩余缺口集中在三类：① **投稿分享转存与 `copy_file` 都没有真实抓包**（`copy_file` 目前只有前端 JS 调用契约，原始 `w.har` 54 条请求里没有一次复制操作）；② 真实 A/B 网盘、TgtoDrive、Telegram Bot 的联调（尤其自动链路在真实环境下的识别/推送结果、电影目录分享的真实链接、`·` 目录名兼容性）；③ 推送隔离的数据层字段。详见文末「未完成项清单」与 `docs/光鸭接口取证.md` 第十、十一节。

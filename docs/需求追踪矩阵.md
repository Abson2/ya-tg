## 未完成项清单（按阻塞原因分类）

### ① 等待抓包 HAR 才能落地（需求文档 8.6）

以下接口**没有实现，也没有猜测参数**。管理页「镜像同步」会直接列出这份清单。

1. 创建文件夹
2. 重命名文件夹（B 库主目录自动插 `*`）
3. 删除 B 库文件
4. 删除目录 / 批量删除
5. 投稿分享转存

拿到 HAR 后可直接补进 `GuangYaWebFiles`，并解除 E9/E12/E15/H11 的限制。当前规避方式：B 库影视目录在光鸭网页端手工建立；旧版本文件保留为 `superseded`，需人工清理；投稿只登记审核，不自动入库。

### ② 等待真实环境联调

- 真实 A/B 目录 ID 与 `copy_file` / `get_task_status` 返回（尤其 `status` 非 2 的取值语义）
- 手工建立 B 库带 `*` 目录后的镜像映射
- TgtoDrive 真实 OpenAPI Token 的关键词读取/回写/回读
- 投稿 Bot 真实 `getUpdates`
- 完结校验的真实 TMDB 数据、手动打标 UI 实测

### ③ 已知设计边界，建议 v0.8.1 加固

- **`QueueItem` 缺 `source/mode/task_id` 字段**：镜像「不推 TG」目前靠模块不写队列 + `publish_after_identify=False` 保证，没有数据层强制。镜像后 B 库扫描产生的 `DistributionEvent` 会保留（`queue_id=0`），后续任一次常规扫描 / 重新扫描库调用 `process_change_events(publish=True)` 时会按分发规则处理成一次作品级更新推送。这符合「内容变化 → 一次更新推送」的设计，但**不保证「镜像带来的变化永不自动推送」**。若业务要求绝对隔离，需给事件与队列项加来源标记并在 `process_queue()` 前过滤。
- `status` 非 2 的其它取值只记录不解释，需要真实返回样本才能补全状态机。

### ④ 不打算实现（按需求文档边界）

- 集成 TgtoDrive 源码 / 部署其容器 / 直连其数据库
- 重复开发已实现的 TG 按钮化分享、精简推送、现有模板

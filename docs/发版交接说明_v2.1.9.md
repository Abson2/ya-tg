## 二、本版三条主线（都是真机报障的真实故障）

**① TMDB 限流不再写死「识别失败」**（线上 1656 个资源被永久放弃）
- 限流是可恢复的瞬时状态，此前与真失败一视同仁写 `identify_status=failed`，而待识别集合本就含 `failed` → 每次重试立刻再撞限流再写 failed。
- 新增独立状态 `rate_limited`（前端显示「**待重试**」）+ 分帧排队（`tmdb.rate_limit_wait_seconds()`，等 ≤3 秒就等，超过则中止本轮）+ 一次性回滚迁移（按失败说明文案判据，真失败不动）。

**② 小时窗口迁移判定写错 + 分类时段死区**（0-8 点全天封死、19 个分类挤在凌晨）
- pristine 改按**形态**判定（含 v2.1.1 的 1 小时整点段）+ 幂等保护。
- 溢出池改为按段序循环复用全部可用段 → 0-8 分类数 **19 → 8**、12-16 覆盖 **2 → 6**、覆盖 0-24 无空洞。
- 新增 `_migrate_category_windows()` 自动迁移存量排期：**只重排已存在行**，不新建行、不改上限、不动用户手工行。

**③ 镜像复制撞光鸭风控后整批失败 + 整轮调度被带崩**（196 failed / 89 pending 卡死）
- 新增 `_copy_file_with_backoff`（仅对 127 重试，退避 1/2/4/8/8 秒），三处 copy_file 调用点全部接入；限流耗尽标 `pending` 而非 `failed`。
- 作品循环整体 try/except → 单部失败只跳过该部，整轮跑完并正常落 `last_run`（此前异常会让 `last_run` 永不更新，看起来像定时停摆）。
- 待重试作品无条件优先，不受部数预算与轮转游标限制。

## 三、部署步骤

```bash
# 1) 备份（升级前必做）
mkdir -p ./backup
cp -r ./db ./backup/db && cp -r ./logs ./backup/logs
cp -r ./data ./backup/data 2>/dev/null || true   # Telegram 登录会话（等同账号凭据）

# 2) 指定版本
# .env: IMAGE_TAG=v2.1.9

# 3) 拉取并重启
docker compose pull && docker compose up -d

# 4) 确认版本
curl -s http://<host>:8787/api/health    # 应返回 "version":"2.1.9"
```

⚠️ **必须补挂 `./data` 卷**（v2.1.8 起新增，不挂则「阅读量」页永远显示「未就绪」）：
```yaml
volumes:
  - ./db:/app/db
  - ./logs:/app/logs
  - ./data:/app/data      # ← 必挂
```
宿主 `./data` 目录属主须为 `10001:10001`（`chown -R 10001:10001 ./data`）。

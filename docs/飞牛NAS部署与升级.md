# 飞牛 NAS 部署与升级教程（v0.8.5）

> 普通用户只需要 `docker compose` 拉官方镜像，**不用 clone 源码、不用本地构建、不用懂 Python**。
> 配置与数据库都在 `./db` 卷里，升级时不要删这个目录。

---

## 一、全新部署

### 1. 建目录

飞牛 NAS 建议放在 docker 共享文件夹下，例如：

```bash
mkdir -p /vol1/1000/docker/ya-tg/db
mkdir -p /vol1/1000/docker/ya-tg/logs
cd /vol1/1000/docker/ya-tg
```

### 2. 放两个文件

**`docker-compose.yml`**（一般不用改）：

```yaml
services:
  ya-tg:
    image: abson2/ya-tg:${IMAGE_TAG:-latest}
    container_name: ya-tg
    restart: unless-stopped
    env_file:
      - ./.env
    ports:
      - "${WEB_PORT:-8787}:8787"
    volumes:
      - ./db:/app/db
```

> `env_file` 必须用块列表写法（`-.env` 另起一行），不要写 `env_file: [.env]`。

**`.env`**：从项目 `.env.example` 复制，只改两项必需值：

```dotenv
ADMIN_PASSWORD=换成你自己的强密码
APP_SECRET=用 openssl rand -hex 32 生成
```

其余保持默认。想锁版本就加 `IMAGE_TAG=v0.8.5`；留空跟随 `latest`。

### 3. 启动

```bash
docker compose up -d
docker compose ps
docker compose logs -f --tail=100 ya-tg
```

看到服务 healthy 后，浏览器打开 `http://<NAS内网IP>:8787`，用 `ADMIN_PASSWORD` 登录。

### 4. 首次配置顺序

1. **光鸭授权**：手机号 + 短信验证码登录，凭证自动加密保存、到期自动刷新。
2. **TMDB 设置**（可选）：填 v3 API Key（32 位 hex）或 v4 Read Access Token（`eyJ...` JWT），代码按格式自动判别。不填也能扫描/建分享/推送，只是没海报简介。
3. **分发规则**：加 Bot / 频道，分别「测试连接」（会真实发一条测试消息），再建规则。
4. **镜像同步（可选）**：填 A 源头库 / B 镜像库目录 ID。**B 库 ID 同时就是扫描根目录，不用在别处再填一遍**。
5. **资源库 → 扫描计划**：选间隔按钮（默认 30 分钟），在资源库页头点「立即扫描」，确认资源入库、识别、海报正常，再看推送。单库用法可跳过镜像同步，直接在这里扫描。

## 二、A/B 镜像库的目录准备（v0.8.0 起，v0.8.1 起可自动创建）

如果不用镜像同步，跳过这一节，A/B 功能完全不影响原有单库用法。

1. 在光鸭网页端准备**两个顶层目录**即可，子目录不用手工建：
   - **A 源头库**：原始资源，Ya-TG 只读遍历。
   - **B 镜像库**：复制目标，也是扫描 / 分享 / 推送的唯一来源。
2. **v0.8.1 起不用手工预建 B 库子目录**：抓包 HAR 已确认 `create_dir` 接口，默认开启「B 库缺目录自动创建」，同步时按 A 库结构 1:1 自动建立：

   | 目录类型 | B 库命名 |
   | --- | --- |
   | 分类目录（动画电影 / 国产电影…） | **原名，不改名、不加 `*`** |
   | 影视主目录 | 主标题按 `*` 规则；**括号里的年份与 TMDB 标记原样保留、前面不加 `*`** |
   | 季目录 / 子目录 | 原名 |

   ```
   A：动画电影 / 大醉侠 (2002) {tmdb-135646} / E01.mkv
   B：动画电影 / 大*醉*侠 (2002) {tmdb-135646} / E01.mkv
   ```

   展示、分享标题与推送永远用标准影视名，不带 `*`。
3. 从网页端地址栏或开发者工具网络请求里读取两个目录的 `parentId` / `fileId`。
4. 管理页「镜像同步 → A / B 库设置」填入 A/B 目录 ID，选间隔，按需设置「每个文件操作后的空闲时间」（默认 1.0 秒，**硬下限 0.5 秒不可调低**），启用。
5. **扫描根目录不用再填**：资源库扫描会自动引用这里填的 B 库 ID。
6. 点「立即同步」，到「同步状态 / 目录映射清单」核对自动创建的目录与已同步文件数。若关闭自动创建，「待创建目录」清单会列出需建立的目录，相关作品标 `blocked`（不是失败），建好后重新同步即可。

详细边界与接口清单见 `docs/配置说明.md`、`docs/光鸭接口取证.md`。

## 三、升级

### 常规升级（推荐）

```bash
cd /vol1/1000/docker/ya-tg
docker compose pull
docker compose up -d
docker compose ps
```

数据库在 `./db` 卷里，容器重建不会丢资源、配置、凭证与已建分享。新版本首次启动会自动做列迁移（如 v0.8.0 的 `finish_locked`、v0.8.1 的 `file_idle_seconds` / `auto_create_dirs`）并创建新增表（如 `mirror_dirs`）。

### 锁定指定版本

改 `.env`：

```dotenv
IMAGE_TAG=v0.8.5
```

然后 `docker compose up -d`。回滚把 `IMAGE_TAG` 改成上一个版本号（如 `v0.7.1`）再 `up -d` 即可；每个 `vX.Y.Z` 标签与 Release 都保留历史版本，不会移动已发布标签。

### 升级后必做

1. **用镜像功能**：在「镜像同步」填 A/B 目录 ID 并保存。
2. **重新扫描库**：资源库点一次「重新扫描库」，补齐新版本的扫描批次、目录链与作品键。
3. **按目录重识别**：老资源缺 `path_hint` / `dir_chain_json` / `share_dir_id` 时，重新扫描后再对需要的作品「重新识别」，整剧分享与作品聚合才会完整。
4. **完结标签**：新装的 `finish_status` 需要扫描后自动回填；判错的用作品卡「完结状态」下拉手动锁定。
5. **升级到 v0.8.4 且 B 库已有空目录**：直接点一次「立即同步」。v0.8.4 会把此前 `copying` / `failed` / `unknown` 的文件记录自动重新发起复制；重试前先核对 B 库，已复制成功的不会重复。**不需要清库、不需要删空目录**。若「文件复制失败 / 待重试」清单里全部指向 `copy_file`，按 `docs/光鸭接口取证.md` 第十节补抓一次网页端「复制到」的 HAR。
6. **升级到 v0.8.5**：默认开启「同步后自动入库识别并推送」，同步结束会自动扫 B 库、识别、按分发规则推送本轮识别成功且有海报的影视。**不做全库群发，也不会补推历史内容变化事件**。若不想让定时同步触发推送，到镜像设置关掉这个开关，或只用「仅同步」按钮；关掉后需要到资源库手动点「立即扫描」。

> 提醒：v0.7.0 曾出现「字段写了但链路没通」的情况。判断某个功能是否真的生效，请按 `docs/需求追踪矩阵.md` 的验收点实测，而不是只看界面有没有按钮。

## 四、常见故障

| 现象 | 处理 |
| --- | --- |
| 推送没生效 | 先看管理页「链路自检」/ `GET /api/diagnostics`，确认卡在 Bot / 频道 / 规则 / 待审核 / 失败哪一步 |
| TMDB 401 / 403 | 管理页「TMDB 设置」重新填密钥；v3 是 32 位 hex，v4 是 `eyJ...` JWT，别混填 |
| 光鸭 `code=120` | 网页端短信凭证被拿去调官方 OpenAPI 了，两套认证不能混用，见 `docs/配置说明.md` 第一节 |
| 国内网络连不上 Telegram | 在管理页「分发规则 → 链路自检」填 `telegram_api_base` 反代地址 |
| 数据库锁 `database is locked` | 确认只有一个容器实例在跑；不要同时开两个 compose 项目指向同一个 `./db` |
| 升级后剧集又变成单集卡片 | 先「重新扫描库」再「重新识别」，补目录链 |
| 镜像同步后没有 TG 消息 | **v0.8.5 已反转旧设计**：同步完成应自动刷新入库 → 识别 → 只推本轮识别成功且有海报的影视。先查镜像设置「同步后自动入库识别并推送」开关与同步状态里的生效配置；再看识别状态/海报/作品级去重；仍无消息则到「链路自检」查分发链路。v0.8.4 及更早版本才是「完成不自动推送」 |
| 同步完没有自动入库 / 识别 | v0.8.5 之前 `auto_identify` 是死配置且「立即同步」硬编码跳过识别；升级到 v0.8.5 后默认开启。若结果提示显示「本次仅同步，未刷新入库」，说明开关关着或按了「仅同步」按钮；排查顺序见 `docs/后台功能使用说明.md` 第一节 |
| B 库目录建好、命名也对，但里面没有文件 | v0.8.4 起看「文件复制失败 / 待重试」清单与同步状态里的「复制失败 / 待重试文件」计数，再点一次「立即同步」自动重试；真实报错若是 `copy_file` 被拒，按 `docs/光鸭接口取证.md` 第十节补抓 HAR |

## 五、备份

停容器后打包 `./db` 目录即可，里面包含 SQLite 数据库（资源、配置、凭证、队列、镜像映射、批次、互动记录）。

```bash
docker compose stop
tar czf ya-tg-db-$(date +%Y%m%d).tar.gz ./db
docker compose up -d
```

恢复时把备份解回同一路径再启动。`.env` 里的 `APP_SECRET` 必须与备份时一致，否则已加密的凭证解不开。

## 日志与数据库体积（v0.8.3）

- **容器内 stdout 日志**：`docker-compose.yml` / `docker-compose.build.yml` 已加 `json-file` 限额 `max-size: 10m` + `max-file: 3`，最多约 30MB，无需手工删 `./logs`。v0.8.3 起需重新 `docker compose up -d` 让限额生效。
- **数据库里的日志/留痕**：管理页「操作审计 → 日志保留与清理」默认保留 30 天 / 每类 5000 条，启动时与每天 03:30 自动清理；也可手动「立即清理」「清空全部日志」。配置加密落库，升级不会丢。
- 升级前照旧备份 `./db/ya-tg.db`；清理只删历史日志，不动资源、目录映射、分享链接与待推送队列。
